Java Development on OpenShift Dev Spaces

This section is performed by the cluster administrator before the workshop begins. It installs OpenShift Dev Spaces and applies the base configuration needed for the exercises.

Prerequisites

  • OpenShift 4.17+ cluster with cluster-admin access

  • oc CLI installed and authenticated to the cluster

  • A Git hosting service accessible from the cluster (GitHub, GitLab, Gitea)

All commands in this page target a single OpenShift cluster. Ensure your oc session is authenticated as cluster-admin before proceeding.

Steps to Apply

1. Install the Dev Spaces operator

What: Install the OpenShift Dev Spaces operator and create the CheCluster instance.

Why: The operator manages the full Dev Spaces lifecycle - dashboard, workspace controller, and plugin registry.

oc create namespace openshift-devspaces
oc apply -f 00-setup/subscription.yaml

Wait for the operator to become ready (~2-3 minutes):

oc get csv -n openshift-operators -w | grep devspaces

Once you see Succeeded, apply the CheCluster:

oc apply -f 00-setup/checluster.yaml
Verify: Dev Spaces is running

Wait for the cluster to become active (5-10 minutes):

echo "Waiting for CheCluster to become ready..."
until [ "$(oc get checluster devspaces -n openshift-devspaces -o jsonpath='{.status.chePhase}' 2>/dev/null)" = "Active" ]; do
  sleep 15
  echo "  Still waiting... ($(oc get checluster devspaces -n openshift-devspaces -o jsonpath='{.status.chePhase}' 2>/dev/null || echo 'Initializing'))"
done
echo "CheCluster is Active!"

Confirm all pods are running:

oc get pods -n openshift-devspaces
NAME                                      READY   STATUS    RESTARTS   AGE
che-gateway-xxxxxxxxxx-xxxxx              4/4     Running   0          5m
devspaces-xxxxxxxxxx-xxxxx                1/1     Running   0          5m
devspaces-dashboard-xxxxxxxxxx-xxxxx      1/1     Running   0          5m
plugin-registry-xxxxxxxxxx-xxxxx          1/1     Running   0          5m

All pods should show Running or Completed.

2. Apply security and resource configuration

What: Create a SecurityContextConstraint for container builds and a ResourceQuota for workspace fairness.

Why: The SCC allows workspaces to run container builds, and the quota prevents a single user from consuming all cluster resources.

oc apply -f 00-setup/container-build-scc.yaml
oc apply -f 00-setup/workspace-resource-limits.yaml
Verify: Configuration applied 
oc get scc container-build
oc get resourcequota devspaces-workspace-quota -n openshift-devspaces
NAME              PRIV    CAPS                          SELINUX     RUNASUSER          FSGROUP     SUPGROUP   ...
container-build   false   ["SETUID","SETGID",...] ...   MustRunAs   MustRunAsRange     MustRunAs   RunAsAny   ...

Both commands should return the resource without errors.

3. Confirm dashboard access

What: Retrieve the Dev Spaces dashboard URL and verify it responds.

Why: The dashboard is the entry point for all participants - they will use it to create workspaces.

oc get route devspaces -n openshift-devspaces -o jsonpath='https://{.spec.host}{"\n"}'

Open the URL in a browser and log in with your OpenShift credentials. You should see the Dev Spaces dashboard with the header banner "Java Development Workshop Environment".

Verify: Dashboard responds 
curl -skI "$(oc get route devspaces -n openshift-devspaces -o jsonpath='https://{.spec.host}')" | head -1
HTTP/2 200

You may see HTTP/2 302 (redirect to login) instead - both are expected.

4. (Optional) Configure the extension registry

What: Point Dev Spaces at a public or private Open VSX registry for IDE extensions.

Why: The embedded registry has a limited set of extensions. Java extensions (Red Hat Java, Maven, Debug) may require the full Open VSX registry.

For internet-connected environments, point Dev Spaces at the public Open VSX registry:

spec:
  components:
    pluginRegistry:
      openVSXURL: "https://open-vsx.org"

For air-gapped / disconnected environments, deploy a standalone Open VSX mirror and configure Dev Spaces to use it:

spec:
  components:
    pluginRegistry:
      openVSXURL: "https://your-internal-openvsx.example.com"
Verify: Extensions are available

After updating the CheCluster resource, confirm the plugin-registry pod restarts. Then open a workspace and check the Extensions view to verify extensions resolve from the configured registry.

Setup Complete

The cluster is ready for participants. Share the dashboard URL with the group and proceed to Step 1: Create Workspace Template.

Reset

Remove Dev Spaces and all configuration applied in this step. Resources are deleted in reverse order - the CheCluster must be removed before the operator subscription to allow proper cleanup of workspace resources.

oc delete resourcequota devspaces-workspace-quota -n openshift-devspaces --ignore-not-found
oc delete scc container-build --ignore-not-found
oc delete checluster devspaces -n openshift-devspaces --ignore-not-found
oc wait --for=delete checluster/devspaces -n openshift-devspaces --timeout=120s 2>/dev/null || true
oc delete subscription devspaces -n openshift-operators --ignore-not-found
oc delete csv -n openshift-operators -l operators.coreos.com/devspaces.openshift-operators --ignore-not-found
oc delete namespace openshift-devspaces --ignore-not-found
